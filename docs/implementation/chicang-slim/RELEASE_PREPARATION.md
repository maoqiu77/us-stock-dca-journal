## 视觉发布额度方案（待实施，现有测试行为未改）

源码目前将视觉每日额度固定为 null，每用户处理并发为 1；文字 AI 的额度不覆盖视觉请求。现有 `AI_VISION_ENABLED` 提供总开关。发布前建议实施以下独立策略：

| 范围 | 建议行为 | 验收依据 |
|---|---|---|
| 每用户额度 | 发布配置要求显式正整数，不接受缺失、null、0 或负数 | 配置非法时服务关闭，不进入上传/模型路径 |
| 全局额度 | 发布配置要求显式每日请求上限，额度与用户额度一起原子预占 | 两个用户并发抢最后额度只有一个成功 |
| 重试计数 | 同识别 request 只计一次；已受理或结果未知不能通过重试重复调用 | 超时、乱序、重复请求、跨日、取消回归 |
| 失败释放 | 仅在确认尚未调用 provider 的失败中释放；调用后失败/取消按已使用处理 | provider 已调用后不能用重试绕过上限 |
| 预算与停用 | 请求上限并不等同金额上限；另设供应商账单预算告警和人工总停用流程 | 平台预算回执、AI_VISION_ENABLED=false 服务端拒绝验证 |
| 测试例外 | 若继续保留无限额测试，要求显式测试环境配置，不能成为发布默认 | 测试配置无法通过发布就绪检查 |

具体额度需要结合供应商单次费用和运营预算确定，本文件不虚构可承担费用，也没有恢复此前用户取消的测试期每日限制。该方案不是已完成的 P1-V03 修复。

## 下一轮云端验收的具体范围

先对已授权测试环境做只读取证：确认环境及非生产属性、三个函数的实际运行时/版本/部署身份、配置项是否存在、定时器配置、集合与存储规则。只记录脱敏标签、版本和存在性，不导出秘密值、真实身份或账本正文。

获得对应测试写入授权后，按以下顺序验收，全部使用专用测试身份和合成数据：

1. 在隔离环境部署与本地 manifest 对应的云包，验证平台安装遵循锁文件；运行时按平台实际 Node 版本复验。部署前保留可回滚版本信息。
2. `portfolioAiCleanup`：核对 `CLEANUP_JOB_TOKEN`、`AI_PAYLOAD_RETENTION_MS`、超时及定时触发消息；准备未识别、取消、过期、删除失败重试候选，等待真实 timer，取得对象不存在及元数据收敛回执。不能手工删除后冒充 cron 成功。
3. 双测试身份：管理集合客户端不可读写、task/file/request/receipt 跨用户访问拒绝；仅测专用合成记录，不对真实用户记录做探测。
4. ACK 与保留期：本地成功保存后检查云请求正文/response 清除，ACK 丢失可重试；本地保存失败不 ACK；独立 timer 清除超期内容且跳过 running 请求。优先使用合成请求结果，不需要真实模型计费。
5. 行情逐源许可：列明公开展示、缓存期限、历史存储、转交模型和回答归档依据，并映射实际 provider 与开关。公开接口可达不作为许可；无依据用途不放行。

真实模型精度、图片上传/删除、云端部署/配置变更均需要与该范围对应的明确授权。本地准备未执行这些外部操作。
