# AIContext v2 设计

## 目标

整理每日 AI 建议和今日追问所使用的投资上下文，使模型更稳定地遵守账户事实、资金限制和分层投资规则，同时减少重复、冲突和假精确建议。

本次保持现有 API、AI Provider 调用方式和 AI 日历记录结构不变，不自动下单，不迁移或删除历史记录，也不接入券商真实现金同步。

发送给外部模型的系统指令、任务说明、章节标题、规则和结构化字段统一使用英文，以降低提示词 token 开销；最终可见回答仍强制使用简体中文。

## 当前问题

- 最新每日提示词约 3.7 万字符，策略参数、引擎参数、持仓、报价和信号存在重复。
- 当前提示词把“跌破 MA120 优先减仓”作为通用要求，但 ETF 信号允许在 MA120 下方按 52 周回撤资金池长期分批投入。
- `cash` 由总资产减持仓历史成本推算，不是券商实时可用现金，但提示词没有表达其可信度边界。
- 输出格式强制要求精确买入触发价和失效价，即使行情为 sample、不可用或依据不足。
- 追问每次重新发送完整上下文和最近 10 条消息，没有字符预算；数据库保留的对话会持续增长。

## 方案选择

采用现有调用链内的规范化上下文构建层，而不是只删减提示词或建立新的外部 API/持久化模型。

理由：只删减不能解决规则冲突和数据可信度；重建独立 API 会扩大范围。规范化构建层可以保留现有前后端契约，同时让每日生成与追问共享同一事实口径。

提示词语言采用“英文指令与结构 + 中文最终回答”的混合方案。相比继续使用全中文提示词，它通常能用更少 token 表达相同规则；相比把所有内容强制翻译成英文，它不会扭曲用户问题、交易备注、标的名称等原始事实。

## 提示词语言约定

- system message、任务说明、输出格式、规则文本、章节标题和 JSON key 全部使用英文。
- 用户输入的额外问题和追问保持原文，不在程序内翻译。
- 交易备注、用户自定义名称等自由文本保持原文；固定枚举值在规范化上下文中转换为英文，例如 `买入` 转为 `buy`、`卖出` 转为 `sell`。
- 平台生成的固定中文原因和风险提示优先转换为结构化英文事实字段；暂时无法无损结构化的说明保留原文，并明确标记为 `source_text`。
- system message 和 user task 都明确写入 `Respond in Simplified Chinese`。输出标题、表格内容、理由、风险提示和执行顺序必须是简体中文；股票代码和通用指标缩写保持原样。
- 不依赖模型自行翻译账户数值或交易事实；所有数值和枚举在发送前完成规范化。

## 上下文结构

构建一份版本化的 `AIContext v2`，包含以下区块：

1. `meta`
   - 上下文版本。
   - 北京时间、纽约时间和常规交易时段状态。
   - 行情使用限制和手动确认要求。
   - `prompt_language: en` 与 `response_language: zh-CN`。
2. `account`
   - 总资产、持仓历史成本和推算剩余资金。
   - 将推算资金明确标记为 `estimated_from_historical_cost`，并说明它不是券商实时可用现金。
3. `strategy_policy`
   - 三层资产角色及各自决策优先级。
   - 只保留 AI 判断真正需要的规范化参数，不再同时输出前端设置和 snake_case 引擎参数。
4. `positions`
   - 每个标的的资产类型、策略角色、股数、成本、目标仓位、止盈止损。
5. `trade_context`
   - 总交易条数、按标的聚合的买卖摘要。
   - 最近相关交易，默认最多 20 条；不再把完整历史流水放进每次提示词。
6. `market_decisions`
   - 按 ticker 合并报价、日内摘要和平台量化信号。
   - 保留 source、时间、MA、RSI、回撤、平台动作、建议金额、理由和限制。
   - 每个事实只保留一个主口径，减少价格和持仓字段重复。

## 决策优先级

统一顺序为：

1. 真实账户与交易事实。
2. 现金、目标仓位和单标的上限等硬限制。
3. 按资产角色划分的策略规则。
4. 平台量化计算结果。
5. 有来源且足够新鲜的行情与日内节奏。
6. AI 的解释和覆盖判断。

资产角色规则：

- 核心 ETF：优先使用 52 周回撤资金池、目标仓位、ETF 上限和极端止盈规则。MA60、MA120、普通 RSI 与普通止损只作背景，不单独阻止既定长期分批投入；平台未分配资金时 AI 不得自行突破资金池。
- 核心科技股：止损、跌破 MA120、仓位超目标和明显过热优先于普通加仓信号。
- 卫星仓：沿用个股风控，且加仓更轻、更慢，减仓降温更早。

AI 可以覆盖平台动作，但必须标记“AI 覆盖平台信号”，引用具体上下文字段，并且不能突破资金和仓位硬限制。

## 行情可信度与价格输出

- `sample` 或不可用数据不能作为真实价格、MA、RSI、支撑阻力或交易信号依据。
- 行情缺少可靠来源或时间不足以判断新鲜度时，AI 必须提示在券商端刷新确认。
- 只有可靠行情才能给出观察区间或条件价；不强制每个标的给精确触发价。
- sample 或不可用行情必须输出“暂不提供精确触发价”，不得通过其他字段推导伪精确价格。

## 每日建议提示词

- system 消息使用英文，只保留不可违反的角色边界、数据可信度规则、优先级和简体中文输出要求。
- user 消息的任务说明使用英文，包含用户额外问题原文以及使用英文 key 序列化的 `AIContext v2`。
- 输出包括生成时间、今日结论、账户判断、标的决策、必要的重点说明、执行顺序和策略反馈。
- 标的决策中的理由必须能追溯到上下文字段；信息不足时明确不确定性。
- AI 返回内容必须为简体中文；若模型未遵守，不在本次范围内增加二次模型翻译调用。

## 追问上下文预算

- 每次追问重新生成最新 `AIContext v2`，避免沿用过期行情和账户状态。
- 数据库继续保存完整对话，不修改现有记录格式。
- 发给模型的历史包含初始日报和最近对话，并受固定字符预算约束。
- 优先保留最新用户问题、最近完整问答和初始日报的压缩摘要；从最旧的中间对话开始裁剪。
- 单条超长消息按字符上限截取并标明已截断，避免不同 OpenAI-compatible 模型因上下文窗口差异直接失败。

## 错误处理与兼容性

- 保持 `/api/ai-advice/generate`、`/api/ai-advice/chat` 及 Responses/chat-completions payload 契约不变。
- 某一标的的日内行情失败时保留该标的的报价和长期信号，并标明日内数据不可用。
- 规范化阶段忽略无法识别的非字典行，不因单条脏数据阻断整个建议。
- 历史 AI 日历中的旧 prompt 原样保留；只有新生成记录使用 v2。

## 验收标准

- 新提示词标识 `AIContext v2`。
- 发给模型的固定提示文本和结构化字段为英文，用户自由文本保持原文。
- system 和 user task 都明确要求输出简体中文。
- 不再出现“旧引擎参数”区块，也不发送完整交易流水。
- 策略原始参数与转换参数不再双份出现。
- 现金字段明确为历史成本推算且非券商实时现金。
- ETF 规则明确 MA120 和普通止损不单独阻止资金池内分批投入；个股仍保持相应风险优先级。
- sample 或不可用行情明确禁止精确触发价。
- 报价、日内摘要和量化信号按 ticker 合并。
- 最近交易数量有上限，并提供全量交易的聚合摘要。
- 发给模型的聊天历史不超过配置的字符预算，最新问题必须保留。
- 现有 AI 生成、追问、Responses API 和 chat/completions fallback 测试通过。

## 验证范围

- 单元测试覆盖规范化结构、规则文本、交易截断、行情合并、sample 限制和聊天预算。
- 单元测试验证固定提示文本不再包含旧中文指令，并包含明确的 `Respond in Simplified Chinese` 要求；用户中文问题保持原样。
- 运行 AI 建议与 AI 设置相关后端测试。
- 运行 API 契约测试，确认前端所依赖的记录字段不变。
- 统计本机真实状态生成的新提示词字符数，但不输出私人持仓或交易明细。
