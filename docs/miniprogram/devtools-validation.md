## J0 存储契约与故障边界

持久主账本 / 备份格式仍为 v2；新增的本地待核验协议显式为 v1：

| 存储键 | 语义 |
| --- | --- |
| `portfolio.wechat.v1.pending-v1.before` | 提交前精确主账本原文（空账本可为空串） |
| `portfolio.wechat.v1.pending-v1.next` | 已生成固定 record/revision 身份的预期完整结果 |
| `portfolio.wechat.v1.pending-v1` | `{version:1,replacement:boolean}` 提交屏障；非空表示尚需核验 |

顺序：先分别保存并回读 before、next，再保存并回读提交屏障；只有三步都通过才写主账本。暂存写入失败时主账本尚未修改。未写入屏障的孤立暂存不自动重放，下一笔可覆盖。主账本回读一致才确认；写后抛错但回读一致也确认成功。主账本确认后尝试清空并回读屏障，再尽力清空两个暂存键。清理失败不改变已确认写入的成功语义；若屏障仍在，新写入继续被阻止，须在设置再次核验。若暂存清理失败，遗留内容仍只在本地，后续提交覆盖，不参与备份导出。

非空屏障阻止新写入；正常读取、导出备份仍可用。页面保留当前输入和预览、显示“核验保存结果”。重启读取屏障，只核验，不自动保存。已存在的修订须身份及完整内容一致；可以在存在其他有效写入的账本上核验交易修订。仅当主账本仍精确等于 before 时提供“安全重试原提交”，复用 next 中全部原修订；两笔明确的新交易即使内容相同仍分别记账。

替换/恢复在主写入尝试时就使旧页面版本失效。恢复前的恢复点仅在第一次替换时保存；核验和安全重试只使用原 next，不重新调用 replace、不覆盖恢复点。结构损坏、缺失证据或内容冲突会保留暂存并停止写入，需导出当前备份并人工检查；不提供静默强制清除或自动合并。屏障读取失败也停止新写入。提交异常携带本次内存中已知的完整预期结果身份，页面将其保留在实例属性中，不放进 setData。其他页面已处理本次提交、或全局待核验身份已变时，原表单保留输入但锁定保存；无法可靠确认身份的原页面只引导到设置核验，不认领后来的提交。主账本已确认成功但清理屏障回读失败时，页面仍保持已保存状态，不能回到普通未保存表单。

单份账本仍遵循原800 KiB限制；before/next分键避免把账本容量减半。保存期间需要额外容纳两份快照，恢复还需恢复点；总空间不足会失败并保留原账本。现有容量预检不承诺实际宿主写入一定成功。本协议面向当前同步单写入端；不承诺与旧版应用、外部写入者或云同步并发写入的原子比较交换。
