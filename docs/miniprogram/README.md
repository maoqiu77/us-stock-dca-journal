# 微信小程序测试版

项目主方向已于 2026-09-10 从独立 App 调整为微信小程序。当前 `0.2.0` 交付在 **W0 离线测试版** 基础上完成 MP0 / MP1 / J0，并完成 AI 新规划的 A0 / A1 本地能力（状态见 [ai-implementation-status.md](ai-implementation-status.md)）。它不依赖服务器、AppID、行情或真实模型。

## 直接导入测试

1. 从微信官方[开发者工具下载页](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)安装工具。账号登录按工具当前提示完成。
2. 在仓库根目录运行 `npm run check:weapp`，然后在开发者工具选择「导入项目」，选择 `apps/miniprogram/dist`（含 `project.config.json`）。本机真实路径与工具结果见[验收记录](devtools-validation.md)。无需先打 zip 包。
3. AppID 选择工具提供的「测试号」或游客调试入口；共享工程使用 `touristappid`。如果当前版本要求登录或申请测试号，按工具提示获取，不要填写他人的 AppID。后端服务选择「不使用云服务」。
4. 点击「编译」。**无需再构建 npm**，构建目录已包含业务与依赖。
5. 持仓页点击「体验示例」，按下面的验收流程操作。设置页「开始新的空账本」可退出示例模式；会保留一个恢复点。

源码构建后也可以直接导入 `apps/miniprogram/dist`。不要导入 `apps/mobile`，也不要直接导入未构建的 `apps/miniprogram/miniprogram`。

**已在微信开发者工具 2.02.2608070、实际基础库 3.17.2 中完成编译及主要离线模拟器验收。** 已验证原账本流程，以及只读上下文预览、明确标记的 fake 分析、自动归档、同会话追问和个人记录闭环，详见[验收记录](devtools-validation.md)。当前工程仍是游客 AppID，控制台仍有 SDK 错误；真机、文件接口、真实 AppID、云端与真实 Provider 验收尚未完成。

## 这版能做什么

| 页面 | 当前能力 |
| --- | --- |
| 持仓 | 期初录入、剩余数量、含手续费成本、每股成本、已实现盈亏、标的详情与主动载入示例 |
| 记录 | 期初与买卖区分、碎股/手续费/理由、更正预览、同日顺序、追加作废修订与版本历史 |
| 复盘 | 按日期查看多条时间线；新增/修订个人记录；区分我的原文、AI 引用与交易引用；从 AI 引用继续同一会话 |
| AI 投研 | 组合、标的、复盘三个入口；只读上下文预览；明确标记的本地 fake 分析与追问；候选筛选暂不可用 |
| 设置 | v3 完整明文备份；文件或粘贴导入、预览摘要、确认恢复、恢复点、新建空账本；投资计划人工确认 |

单账户、USD、美股股票/ETF、多头。现金未知、历史不完整；成本不等于市值，不展示虚假行情、净值或收益率。AI 页只运行确定性的本地 fake Provider，所有结果均标为“离线合成演示 · 非真实 AI / 非投资建议”，后续才会在 A2/A3 接受控服务。

无服务器、登录、自动网络请求或自动下单。数据仅在当前小程序本地保存；换机或清理数据前要导出。备份为明文，包含交易和笔记。测试版不是原 App 规划中的加密数据库，**不继承 SQLCipher / SecureStore 的安全能力承诺**。

当前支持读取本小程序 v1 / v2 / v3 JSON，新完整导出使用 v3。v1/v2 导入会建立新工作区并把旧复盘原文一次性迁为个人记录；v3 包含金融账本、日记、会话、分析、来源和计划。旧版软件不支持 v3，不支持桌面数据库、旧 App 备份或券商文件直接导入。金融账本与每个工作区分区分别最多 800 KiB；超过限制时拒绝保存。个人记录每条 4000 字，交易表单备注 2000 字。详细迁移与回退见 [存储 ADR](ai-storage-adr.md)。

## 十分钟手工验收

所有金额使用虚构输入，不需要实际持仓。

1. 首次启动：零记录、空持仓，没有自动注入交易。
2. 记一笔：QQQ、ETF、买入 2 股、价格 10、手续费 1。先预览，再确认保存。持仓成本应为 **21.00**，每股 **10.5000**。
3. 同日或之后卖出 0.5 股、价格 14、手续费 0.2。剩余 **1.5 股**，成本 **15.75**，已实现盈亏 **1.55**。
4. 尝试卖出 2 股：提示持仓不足，不新增记录。
5. 作废第 2 步的买入：因存在后续卖出而拒绝。先作废卖出，再作废买入，可回到空持仓；原始记录保留作废状态。
6. 在复盘同一天新增两条个人记录；编辑其中一条只新增该条修订。草稿未保存时切换日期要确认。
7. 在 AI 投研先查看只读上下文，确认现金、实时价和未确认计划保持缺失；运行 fake 分析，回到复盘看到 AI 引用，再进入同一会话追问。
8. 设置页复制或导出 v3 完整备份。通过粘贴或文件读入，检查六类范围与摘要，在确认前应不改变账本。
9. 恢复有效备份后，点击「恢复上一次替换前的数据」，确认金融账本与工作区同时恢复。此操作保留恢复点，不交换两份数据。
10. 错误 JSON、非本小程序 JSON、损坏引用或超过容量的数据应明确拒绝，原数据保留；真机阶段另验文件接口、前后台和存储配额。

## 开发与自动验证

在 implementation 根目录使用 Node.js 24：

```bash
npm ci
npm run check:weapp
```

构建产物在 `apps/miniprogram/dist`。修改后运行 `npm run build:weapp` 再在工具中编译。需要重新生成压缩包时运行 `npm run package:weapp`（需要系统 zip 命令），输出到 `dist/wechat`。`project.private.config.json` 与产物已忽略，不要提交 AppID 私有配置或设备备份。构建固定为游客配置，不拷贝私人配置。

```bash
npm run test -w @portfolio/domain
npm run typecheck -w @portfolio/domain
npm run test -w @portfolio/ai-context
npm run typecheck -w @portfolio/ai-context
```

核心打成单个 CommonJS 包；页面直接 require 共享核心，避免重复打包。Intl 兼容层使用支持 ES2018 的固定版本；校验库关闭动态代码生成。内存中的假 wx 存储仅用于主机测试，不宣称覆盖微信平台本身的实现。

## MP0 / MP1 使用与兼容说明

- 已有持仓：首次持仓页选择录入期初，填写同一账户的统一期初日期、标的、数量、确认总成本。总成本包含该持仓的已确认成本，不填写当前市价。期初不计入买卖笔数，历史完整性与现金继续为未知/不完整。
- 从第一笔开始：选择记一笔交易；新增记录默认同日末尾。补录或更正可选择同日明确位置，保存时完整回放后续记录。
- 更正：从记录的更正入口编辑，预览数量、成本、已实现盈亏及成交金额/手续费/支出或净收入后确认。旧版本保留，过期编辑拒绝；超卖错误不能通过缩减数量自动“修复”。
- 详情：持仓卡和记录可进入标的详情；清仓后仍能查看历史盈亏、期初、交易原因和修订。卖出可卖量按选定日期及同日位置计算。
- 时钟异常：校准设备时间前首页暂不显示金额，标的详情显示标注时点的已保存事实，仍可导出备份，新交易写入暂停。不要把异常时显示的时点当作实时行情或历史查询结果。
- 故障数据：设置中的原始故障数据导出不依赖 JSON 解析；原文可能不是有效备份，仅用于另存和排错，不会自动修复或覆盖账本。
- 恢复点只保存“上一次替换之前”的账本；它不是每笔交易自动备份。存储写入和回读无法确认时，不会显示保存成功；请使用页面或设置中的“核验保存结果”；确认未写入后只能“安全重试原提交”。待核验期间暂停新写入，重启也不会自动重放。

### 独立手算样例

期初 QQQ 10 股成本 1000；之后买 2 股 × 120、费 1，变为 12 股成本 1241。再卖 3 股 × 130、费 1，消耗期初成本 300，剩余 9 股成本 941、已实现盈亏 89。把后续买入价更正为 125，剩余成本变为 951，已实现盈亏仍为 89。

### 回退边界

代码回退不等于数据格式降级。已经保存 v2 数据时，先使用本版导出完整 v2 备份并私人保管；不要用旧版直接覆盖它，也不要删除新字段伪装成 v1。原 v1 迁移副本只代表升级之前的数据，不包含后续期初和更正。需要回到旧版时，使用独立测试环境恢复原 v1 备份，保留原环境的 v2 数据供重新升级后使用。

本轮没有接真实模型或云端，没有上传体验版、执行审核或发布；真实 AppID 和 iOS/Android 真机验收仍是 `pending_external`。A0/A1 的最终检查与回退细节以 [ai-implementation-status.md](ai-implementation-status.md) 为准。
