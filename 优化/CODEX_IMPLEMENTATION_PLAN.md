## 0. 执行约束

### 0.1 开始前必读

先阅读仓库 `AGENTS.md`、当前目录适用的其他约束、最新 README、小程序发布准备文档、根 `package.json`，再阅读主报告。

记录 `git rev-parse HEAD` 和 `git status --short`。主报告没有固定 SHA；遇到源码已变化，应重新验证对应发现，不要为了迎合报告把已修好的问题“再改一次”。

不要删除、覆盖或自动提交用户尚未提交的改动。不要上传真实持仓、原始截图、对话、密钥、备份及生产环境文件。未经用户明确授权，不进行生产部署、开通供应商收费能力或改变真实用户数据。

### 0.2 优先级与完成状态

主报告中的 Fxx 是发现编号，Rxx 是待验证风险。A 仅表示静态路径明确，并不免除复现测试。

| 状态 | 使用条件 |
|---|---|
| DONE | 实现、必需测试和验收均完成，有实际输出 |
| PARTIAL | 部分实现可交付，但退出条件尚未全部满足 |
| BLOCKED | 缺少必要环境、凭据或真实验证条件 |
| NOT APPLICABLE | 该客户端本轮不在发布范围，并说明依据 |
| NOT RUN | 测试未执行，不能记为通过 |

小程序和桌面可以独立发布。桌面专属缺陷不能算作小程序已经受影响；但继续发布桌面时，也不能拿小程序的修复代替桌面验收。

### 0.3 不改变的产品边界

保留本地优先和无 AI 可使用；不把 screenshot/checkpoint 当交易；不自动交易；不引入生产假数据；不随意统一不同币种；不将 AI 推测提升为用户已确认事实。

已有的结构化结果、来源快照、原文检索、工作区恢复、outbox、授权及生产构建检查应复用。需要修改时先加回归测试，而不是另起一套平行实现。

### 0.4 拟新增文件的标记

下面标为“拟新增”的路径只是建议，执行前应检查是否已有同类模块或测试，优先合并进现有结构。未标注为新增的路径来自本次已检查的仓库入口或源文件。

## Phase 01 — 修复小程序估值、日变动与截图适用性

**目标：** 未知不变零，历史截图不冒充当前金额。  
**对应：** F01、F02、F12 的数据基础、R01。  
**前置：** Phase 00。  
**不做：** 不在这个阶段重排所有页面，不把修正公式当成实现了完整日收益核算。

### 重点文件

- `apps/miniprogram/src/service.ts`
- `apps/miniprogram/miniprogram/pages/overview/index.js`
- `apps/miniprogram/miniprogram/pages/overview/index.wxml`
- `packages/market-data/src/contracts.ts`
- `apps/ai-gateway/src/market/twelve-data-provider.ts`
- `apps/ai-gateway/src/market/eastmoney-us.ts`

### 任务

**01.1 抽出可测试的展示估值计算。** 先定位是否已有等价模块；否则拟新增小范围纯函数，例如 `apps/miniprogram/src/valuation-display.ts`。不要把应用其他所有逻辑一起搬走。

**01.2 修复价格变动基数。** 首选同一报价对象的 price 与 previous close。清楚区分价格变动估计与完整当日盈亏；缺少有效基准时返回未知，给出 reason code。不要为了展示数值，混合两个供应商或两个时间段的价格和涨跌幅。

**01.3 统一截图有效性判定。** 行内金额、汇总、收益率、导出必须使用同一个判定；数量比较采用 Decimal 规范化。数量没变但基线、成本或账本版本发生变化，也要重新判断。

**01.4 分离当前估值与历史参考。** 保留历史截图及观察时间，但失效截图不增加当前行情覆盖数，不构造当前盈亏。检查页面转换层是否仍存在第二次无条件回填。

**01.5 检查截止时间。** 所有价格后备路径必须遵守选定估值截止时点及可知时间；不能绕过已有估值门槛。发现现有历史功能不支持正确的 as-of 语义时，先明确禁用不受支持的展示，不用当前行情假装历史结果。

### 必测算例

| 输入 | 期望 |
|---|---|
| q=10，昨收100，现价110 | 当前数量价格变动为 +100，不是 +110 |
| q=10，昨收100，现价90 | 为 −100，不是 −90 |
| q=10，昨收100，现价100 | 为 0 |
| 有当前价、无可用昨收 | 日价格变动未知 |
| 截图 q=10、市值1000，随后卖出5，无报价 | 当前 q=5，当前市值未知，历史截图仍可查看 |
| 卖出后买回同数量，但成本改变 | 不能仅凭数量相同继续套用旧截图盈亏 |
| 一项缺价、另一项有价 | 显示已知部分及覆盖数，不显示完整合计 |
| 仅观察标的有报价、全部持仓无报价 | 不产生持仓日盈亏 0 的假象 |
| CNY 与 USD 并存且无汇率 | 分币种显示 |
| 某价格在截止时间后才可知 | 不纳入历史估值 |

### 验收与回滚

领域/服务测试和受影响页面测试通过；保留已有持仓校准能力。此阶段优先避免存储 schema 变更；如果确需变更，应拆出迁移测试与可恢复备份。

**退出条件：** 不能以“加了一个非实时标签”替代金额逻辑修复。

## Phase 02 — 修复桌面金额口径与持仓截图写账语义

**目标：** 桌面继续提供服务时，不能输出看似完整但语义错误的账户历史。  
**对应：** F03、F04。  
**前置：** Phase 00；共享算例参考 Phase 01。  
**范围：** 桌面发布必需；纯小程序发布可以单独追踪为桌面待办。

### 重点文件

- `apps/web/src/features/platform/views/dashboard-view.tsx`
- `apps/web/src/features/charts/overview-panel.tsx`
- `apps/web/src/features/platform/trading-data.ts`
- `apps/web/src/features/platform/trading-data-context.tsx`
- `apps/web/src/features/platform/views/position-screenshot-import.tsx`
- 桌面 API 的交易数据模型、持久化和相关测试：修改前继续追踪真实调用，不假设仅改前端即可。

### 任务

**02.1 去掉静默成本价回填。** 让 market value、unrealized PnL 和日变动在缺数据时为未知；展示已知部分、覆盖数和时间。真正空仓的 0 与缺行情分开。

**02.2 修正卡片名称与现金含义。** 将只有持仓浮盈的指标准确命名。检查所有桌面视图、导出和 AI 上下文，防止只有首页改名而后台仍将推算现金当成真实现金。

**02.3 设计最小校准适配。** 先核查现有领域与旧版导入结构，再引入 opening balance / checkpoint 的桌面适配。新增截图不通过虚构买卖归零。不可将后端仍旧计算的流水与前端新算法悄悄分叉。

**02.4 引入导入差异预览。** 区分局部与完整截图。完整覆盖前列出遗漏标的；存在识别失败或不完整图片时，禁止默认认为所有未识别持仓为零。

**02.5 迁移旧合成事件。** 先导出和预演；可靠可判别的旧导入转换为校准引用；无法判别的留为待确认，不自动删除。迁移须保留真实成交与用户原始备注。

### 验收

截图导入前后真实成交笔数不变；真实交易记录不丢失；重复导入无新成交；变更后服务端、桌面总览和 AI 上下文数值一致；旧备份迁移后能完整回读。

### 回滚

先写新存储副本并校验，再切换；保留原始备份。不能以反向造一串交易作为回滚方法。若兼容无法完成，保持旧数据只读并明确阻断新的错误导入，而不是带着静默损坏发布。

## Phase 03 — 发送范围、删除策略与生产费用保护

**目标：** 用户知道数据将发到哪里，公开服务拥有可验证的成本上限。  
**对应：** F05、F10、F18、R03、R04。  
**前置：** Phase 00。  
**不做：** 不替用户实际开通云服务，不假定有生产验证权限。

### 重点文件

- `apps/web/src/features/ai-journal/embedded-composer.tsx`
- `apps/api/app/modules/ai_journal/service.py`
- `apps/miniprogram/miniprogram/features/conversation/index.js`
- `apps/miniprogram/src/workspace/repository.ts`
- `apps/ai-gateway/cloud/portfolioAi/index.js`
- `apps/ai-gateway/scripts/build.mjs`
- `docs/implementation/chicang-slim/RELEASE_PREPARATION.md`

### 任务

**03.1 桌面增加用户可感知的范围确认。** 不是只调用 preview API。首次说明数据类别和接收方；稳定范围可在用户明确选择后简化重复操作，扩大范围或切换接收方时重新确认。

**03.2 排除项必须贯穿自动检索。** 用户撤回、删除或本轮排除的原文，不能被其他上下文分支加回来。系统欢迎语等系统文本与用户原文分开分类。

**03.3 明确删除依赖图。** 展示删除原文、派生 AI、关联想法和回访的影响。检查恢复点、备份恢复、进行中的请求与旧来源是否可能让已删除内容重新进入新上下文。保留策略须与 UI 承诺一致。

**03.4 独立视觉预算。** 生产视觉能力启用时要求有效的用户与全局额度；引入原子预占、请求幂等及熔断。供应商已经被调用或结果未知时，不能仅因取消就返还可重复消耗的额度。

**03.5 不破坏明确的测试配置。** 保留隔离测试环境可选不限额；生产拒绝使用未明确批准的不限额配置。所有设置都应有环境标识，不把开发开关复制进生产清单。

**03.6 接入发布门禁。** 增加生产图、云包、Gateway 测试和预算配置检查；生产凭据、授权、清理回执及供应商权限需要真实验证的项目，分别记录未完成项。

### 必测

两测试身份隔离；预算最后一个名额并发竞争；重复 requestId；模型返回超时未知；用户取消；正文日志脱敏；切换接收方；删除后自动上下文排除；旧备份恢复后 outbox 不自动重发。

### 验收与回滚

客户端取消确认时不得发起模型执行；生产开启视觉却没有有效预算时 fail closed；老请求状态查询不新增执行。回滚代码不能导致预算账本丢失或已执行请求被再次执行。

## Phase 04 — 修复日历、条目详情、缓存与导航

**目标：** 每一个日期和记录类型都可以自然使用。  
**对应：** F06、F07、F08、F11、F14。  
**前置：** 本轮相关数据契约已稳定。  
**不做：** 不把外部财经事件源混入第一版，不同时保留两条新的 AI 写入链路。

### 重点文件

- `apps/web/src/features/platform/views/ai-advice-view.tsx`
- `apps/web/src/features/ai-journal/embedded-composer.tsx`
- `apps/web/src/features/platform/platform-workspace.tsx`
- `apps/api/app/modules/ai_journal/calendar.py`
- `apps/miniprogram/miniprogram/pages/research/index.js`
- `apps/miniprogram/miniprogram/pages/research/index.wxml`
- `apps/miniprogram/src/workspace/repository.ts`

### 任务

**04.1 桌面七列月历。** 加星期标题和月初偏移，所有有效日期可选择。空日期出现“写手记”而不是禁用。有记录、今天、选中和待回访使用不同的可访问状态。

**04.2 类型化的条目分发。** 检查实际 CalendarEntry 联合类型，分别打开手记、分析轮次、量化关联和历史记录。失败或结果未知的分析打开状态详情，不提前无声返回；无法恢复的旧引用显示具体原因。

**04.3 收敛旧版记录。** 使用只读适配器展示旧 AI 日历记录，新的记录走唯一写入路径；不强迫用户立刻迁移所有历史正文。

**04.4 明确归档日。** 桌面个人手记支持选择归档日期，保留真实创建和修订时间。业务月边界按既有时区约定转换后查询，不能用 UTC 字符串截取代替业务日期。

**04.5 范围查询。** 桌面月份摘要只取范围内计数；日清单统一稳定排序并分页。根据实际查询计划补索引。小程序复用现有工作区，必要时建立可重建索引，不破坏来源存储。

**04.6 缓存失效。** 新建、修订、删除和跨日移动均更新相应日/月；AI 完成和状态变化也更新相关条目。统一 query key 工厂或事件接口，防止各组件漏刷。

**04.7 导航可恢复。** 桌面 URL 承载视图、日期、会话和稳定标的 ID；前进、后退、刷新与直接进入保持一致。小程序使用平台导航适配，不在 URL 放敏感正文和金额。

### 验收

覆盖闰日、月首不同星期、无记录日期、多类型同日、失败分析、跨午夜完成、补记历史日期、删除最后一条记录以及跨月修订。

从总览跳到某标的研究，再返回，总览筛选仍在；复制桌面日期/会话链接后能恢复对应上下文，失效引用有明确降级。

### 回滚

日历索引必须可重建；不删除原始记录。新归档日期字段有向后兼容读取；旧记录缺字段时按已记录的旧规则读取，并注明来源，不能擅自重新归档。

## Phase 05 — 连接“想法、决定、回访、真实交易”

**目标：** 形成最小长期复盘闭环。  
**对应：** F09，主报告第 6、7、10 章。  
**前置：** Phase 04；发送和删除策略遵循 Phase 03。

### 重点文件

- `apps/miniprogram/miniprogram/features/conversation/index.js`
- `apps/miniprogram/miniprogram/features/conversation/index.wxml`
- `apps/miniprogram/src/workspace/repository.ts`
- `apps/miniprogram/src/service.ts`
- 实际 JournalEntry / run / message / source schema：先从现有导入定位，再扩展
- 桌面相应应用服务：在小程序最小链路验证后复用契约，避免同时重写两端

### 任务

**05.1 保存想法时保留来源。** 使用已经选中的 messageId，关联 run、conversation 和标的。原有 `savePersonalNote` 接口含 ID 与修订参数，不能把新的来源 ID 误塞进原有参数位置；采用具名输入或兼容重载。

**05.2 区分用户正文与 AI 引用。** 用户自己写下的内容仍为原文；直接引用 AI 的段落保留 AI 来源身份。历史未关联笔记保持空引用，不推测关联关系。

**05.3 复用已有决定类型。** 检查 `user_decision` 的现有 schema、读取和写入支持，补最小 UI 与验证。决定类型先限定为暂不行动、接受部分、保留意见、安排回访，避免直接加入复杂交易指令。

**05.4 关联实际交易。** 从已确认的账本事件选择关联，双向可查看；不解析一句“我买了”便自动新增成交。关联同一事件重复操作应幂等。

**05.5 最小回访队列。** 第一版支持用户确认的日期和有限结构化条件，结果为等待、可核查、数据不足、已完成、已取消。任意自然语言条件不能直接执行为可编程规则。

**05.6 明确检查时机。** 没有真实后台执行通道时只在应用打开时检查，UI 如实说明；不伪造实时通知，不引入未经授权的推送或外部服务。

**05.7 删除与迁移。** 所有关联校验工作区归属；删除原记录后按 Phase 03 策略处理引用和派生内容。旧备份迁移后关联缺省值正确、outbox 不自动重发。

### 验收

从 AI 回答写想法后，能从想法返回原回答；从日历找到决定并查看所引用快照；修改和撤销决定不会产生真实交易；关联成交不会重复计账；数据不足时回访不误判条件达成。

### 回滚

新增结构先独立版本化和备份。回访计算是派生读取，停用后不影响真实账本。降级版本不支持新关联时必须明确拒绝写入或只读。

## Phase 06 — 总览信息层级、数据状态与新用户引导

**目标：** 不依赖 AI，新用户也能完成首次记录并看懂账户。  
**对应：** F12、F13、F16 的使用入口；主报告第 5、9 章。  
**前置：** Phase 01；桌面涉及金额的部分依赖 Phase 02。

### 重点文件

- `apps/miniprogram/miniprogram/pages/overview/index.js`
- `apps/miniprogram/miniprogram/pages/overview/index.wxml`
- `apps/web/src/features/platform/views/dashboard-view.tsx`
- `apps/web/src/features/charts/overview-panel.tsx`
- `apps/web/src/features/platform/platform-workspace.tsx`

### 任务

**06.1 首屏只保留关键状态。** 币种、估值及覆盖范围、持仓浮盈、价格变动口径和最多三项待查看事项。详情下沉，不删除高级用户的详细表格入口。

**06.2 列表双模式。** 小程序默认简洁卡片或紧凑列表，可切换详细；桌面默认真实持仓，观察列表单独切换。保存用户排序、列选择和展开状态。

**06.3 来源状态进入行内。** 显示报价时间或净值日、参考/延迟/过期/缺失类型，并能查看具体来源。长名称、大字号和负数金额不应截掉单位或符号。

**06.4 可解释的待查看事项。** 只从确定规则生成：缺成本、校准冲突、报价缺失、未完成请求、到期回访。没有用户确认的阈值时不生成“超出你的目标”。

**06.5 任务式引导。** 支持记录当前持仓、录入交易和隔离演示；完成后核对结果。AI 未配置或未获授权时，本地记录链路依然可用。

**06.6 统一错误出口。** 按“原因、影响、下一步”展示，并提供不含敏感内容的诊断信息。不要让失败操作使输入内容丢失。

### 验收

新用户在无 AI 配置、行情不可用、弱网及离线情况下，仍能保存本地记录并理解未知字段。分别测试小屏、大字号和桌面键盘路径。

本阶段不要求制作没有完整数据支持的净值或回撤曲线。

### 回滚

UI 模式切换仅影响呈现，不修改账本。旧列表保留短期回退开关，但不得回退 Phase 01/02 的数字正确性。

## Phase 07 — 看板稳定刷新、保存视图与研究跳转

**目标：** 用户能够连续查看和比较，不因刷新丢失上下文。  
**对应：** F15、R02，以及主报告第 8 章。  
**前置：** 行情身份、质量和时间契约已确认。

### 重点文件

- `apps/miniprogram/miniprogram/pages/market/index.js`
- `apps/web/src/features/market-board/market-board-view.tsx`
- `apps/api/app/modules/market_board/router.py`
- `packages/market-data/src/contracts.ts`
- 对应行组件、详情组件及客户端缓存：按实际调用继续定位

### 任务

**07.1 先保留再刷新。** 首次无数据时可用骨架，已有行时保留旧内容及时间；刷新失败可重试，不将旧数据标成刚更新。

**07.2 保存视图。** 明确持仓、观察、市场参考三个数据来源。记住分段、排序、过滤和选中项；用户已清空自选时，后续初始化或升级不能自动补回种子。

**07.3 稳定排序。** 不在用户操作期间强制移动当前行。缺失值按明确规则处理，不能当 0 参与收益排序。

**07.4 列的含义随资产明确。** 净值日、价格基准、参考溢价时间分别说明。不兼容资产的比较项隐藏或解释，不用统一“实时价格”掩盖差异。

**07.5 最小比较。** 最多先支持两至三个标的，显示币种、区间和覆盖；不在数据不足时输出精确优劣排名。

**07.6 研究入口带上下文。** 使用稳定身份和数据引用，不只传 ticker。返回保持原看板位置。全局刷新和局部刷新分别测试，确认真正更新了目标数据。

### 验收

弱网、部分标的失败、整批失败、刷新中切换分段、页面返回、用户清空自选和连续排序均不丢失真实状态。不会把上次缓存标记为新鲜数据。

### 回滚

保存视图为独立偏好，不能覆盖账本或自选真实内容。缓存结构升级失败时可丢弃缓存重新获取，但不能丢弃用户自选。

## Phase 08 — AI 相关性、变化解释与复盘评测

**目标：** 证明 AI 更有用，而不是只把提示词写得更长。  
**对应：** 主报告第 7、11 章。  
**前置：** Phase 03、05。

### 重点文件

- `apps/api/app/modules/ai_journal/automatic.py`
- `apps/api/app/modules/ai_journal/agent/memory.py`
- `apps/api/app/modules/ai_journal/context.py`
- `apps/api/app/modules/ai_journal/service.py`
- `packages/ai-context/src/index.ts` 及实际导出的相关契约
- 小程序现有研究构建与结果校验模块：按实际调用定位
- 拟新增或复用：AI 评测夹具及运行报告目录

### 任务

**08.1 固定评测集。** 使用去敏或合成数据，记录允许来源、禁止结论、关键限制、期望补问。先测基线，再改检索或提示。

**08.2 先改善现有检索。** 保留原文出处、时间过滤、去重和用户排除；处理相似 ticker、过时规则、矛盾手记以及来源已删除的情况。不默认升级向量数据库。

**08.3 确定性变化比较。** 对两次可比快照计算持仓、计划、证据和缺失信息变化，再交给 AI 解释。不可比时明确指出原因，不能自动用新数据覆盖旧快照。

**08.4 每条重要事实有依据。** 数值引用领域结果，来源 ID 必须属于本次清单；用户假设、AI 推断和事实分开。模型拒绝或资料不足时保留有效状态，不伪造完整研究。

**08.5 复盘优先评价过程。** 根据当时可知资料和已确认计划检查一致性。收益只在数据与口径满足条件时报告，不输出无根据的 AI 胜率。

**08.6 成本与反馈。** 记录成功保存的研究成本和去敏错误类别；不要收集完整提示词作为默认埋点。用户反馈聚焦是否相关、是否漏信息、是否可回溯。

### 验收

强制用例中无越界引用、无将未知金额认作确定值、无已删除原文回流、无未来信息泄漏。人工对照评审记录正负样例，不用模型自评分代替评测。

### 回滚

检索和提示版本可追溯；旧结果保留原模型、提示/配置版本及来源快照。回退新策略不应改写历史分析。
