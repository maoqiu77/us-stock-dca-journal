## 1. 建议采纳什么

**采纳两组建议共同的产品主线：可信持仓 → 相关变化 → 有依据的分析 → 用户自己的判断 → 到期复盘。先修可信度和数据保存，再完善使用路径，最后扩展长期记忆。**

AI1 更适合指导当前桌面工作台：它覆盖保存冲突、生产示例行情、Agent 安装落差和备份恢复。AI2 的补充价值主要在小程序：日变动公式、截图金额失效、想法来源丢失和视觉费用保护。两者应合并使用，但不能把各自的 Phase 顺序直接拼接。

推荐按下面的取舍执行：

| 决策 | 采纳内容 | 理由与边界 |
| --- | --- | --- |
| 立即采纳 | 缺行情不补成本、不补零；正确命名金额；分币种、分时点、标覆盖率 | 这是所有页面和 AI 分析的基础，不属于可选美化 |
| 立即采纳 | 生产路径彻底隔离 sample；真实缓存保留原观察时间 | 新看板已改，但旧接口仍需修复，不能只关闭一条路径 |
| 立即采纳 | 保存状态、冲突检测、可恢复备份、损坏保护 | 优先于新增数据实体；不能等到路线图末尾才验证恢复 |
| 立即采纳 | 持仓校准与真实成交分离；截图完整性与差异预览 | 新写入先纠正，旧历史另做可审查迁移，不能靠备注批量删除 |
| 立即采纳 | 补齐已有日历、统一对话、可见发送范围、来源排除 | 当前已有部分修复，应验收并补缺口，避免重做 |
| 近期采纳 | 看板稳定刷新、统一标的入口、可恢复导航、手机简洁持仓列表 | 连接现有功能，投入比全面换 UI 更可控 |
| 小步采纳 | 用户确认的判断卡、手动复盘日期、简短投资政策 | 先完成一个标的一条闭环，不一开始建设复杂决策平台 |
| 条件采纳 | 小程序金额修复与想法关联；公开视觉服务的预算门槛 | 分客户端交付；小程序缺陷不能当作桌面缺陷，云门槛按实际启用能力生效 |
| 按证据采纳 | 月份查询、分页、索引、检索优化、准备阶段并发 | 先测现有行为和规模，优先消除明确的全量读取与不必要请求 |
| 暂缓 | 向量数据库、新多 Agent 编排、跨端自动同步、恢复原生 App 开发 | 当前瓶颈不是缺新技术栈；保留已有 Agent 和量化功能 |
| 暂缓 | 精确账户日收益、TWR/MWR、历史净值回填、ETF 穿透、多账户统一资产 | 依赖现金流、公司行动、历史持仓和可靠估值，不用当前截图反推历史 |
| 暂缓 | 条件实时监控、自动周报推送、研究卡分享、更多比较视图 | 先证明记录和复盘有人使用，再投入通知、后台运行与分享能力 |
| 不采纳 | 自动交易、模型自动写账、默认全量上云、为美观填补未知数字 | 超出产品边界且损害记录可信度 |

**默认实施顺序以当前正在改动的 Web/FastAPI 为主线，小程序另列专项。** 这是本方案对开发顺序的建议，不改写 README 中“小程序为当前对外产品”的定位。若下一次明确只发布小程序，应先执行 M01 和该端适用的发布门槛，不必等待桌面全部功能完成。

7. **契约统一不等于全面重写。** Python 与 TypeScript 使用共同合成金样核对；不要求 Python 执行 TS，不一次合并所有表，也不机械拆大文件。

## 4. 全阶段共用的事实与时间契约

这些是实现的最低语义要求，字段名须映射当前已有类型，不另建同义类型体系。

### 4.1 金额、覆盖与价格

- 按币种输出；身份包含市场、交易所或映射、资产类型、币种和份额类别，ticker 不作跨市场唯一身份。
- 区分“有报价可算市值”和“同时有成本可算浮盈”。令 K 为有效估值集合，P 为 K 中成本也有效的集合：市值为 `Σ(q×p), K`；浮盈为 `Σ(q×p−剩余成本), P`；收益率分母只用 P 的剩余成本。分别展示两类覆盖数。
- 有持仓但全缺报价时是未知；确认空仓时持仓市值可为 0。成本为零、未知或口径不适用时，不生成误导收益率。
- 不再静默用成本、历史截图、来源不明的 signal 数字替代当前行情。可靠旧行情可展示，但必须有原观察时间、质量和采用口径；`fetched_at` 不能冒充 `as_of`。
- 当前数量价格影响优先为 `q × (price − previous_close)`，且同一报价、时段、复权和币种基准一致。不是完整账户当日盈亏；缺昨收或基准不兼容则未知。
- 截图只是带观察时间和账本版本的历史证据。数量、成本、基线或冲突变化时统一失效；即便未变化，也不得悄悄提高当前行情覆盖率。
- 现金只来自明确记录/对账或清楚标记的用户输入；`总资产设定 − 持仓成本` 只能属于估算预算，不作为实账现金参与 AI 仓位结论。
- 财务核心计算复用现有 Decimal 能力和字符串契约；避免跨端舍入不一致。不要求在首轮一次替换全项目所有 number。

### 4.2 记录与历史

- 真实成交、期初、校准、个人原文、AI 结果、用户确认的决定分别分类；引用关联不复制成交。
- 业务归档日与真实创建/修订时间分开；沿用北京时间归档和各市场交易日规则。
- “查看当时分析”读取原冻结快照；“现在重新审视”创建新分析并回链。今天补记旧日期的内容不得成为过去已知证据。
- 检索失败、被排除、数据不存在、超出容量、版本不可用分别表达；未检索到不等于用户从未想过。
- 删除原文后新上下文不得重新带入正文；历史快照保留、脱敏或清理需有明确产品策略。既有不可变来源不能静默重写，彻底清理使用独立、可审查流程。
